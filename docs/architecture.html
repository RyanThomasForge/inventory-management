Factory Inventory Management System

System architecture, tech stack, and data flow overview

Vue 3 FastAPI In-Memory JSON Data No Database

Tech Stack

Frontend

Vue 3 + Vite

  • Composition API throughout
  • vue-router 4 for view routing
  • axios for HTTP calls
  • Custom composables for shared state (no Vuex/Pinia)
  • Custom i18n (en / ja) with localStorage persistence
  • Served on :3000 via Vite dev server
Backend

Python + FastAPI

  • Single-file API in server/main.py
  • Pydantic models for request/response validation
  • Uvicorn ASGI server on :8001
  • CORS open (allow_origins=["*"])
  • Run via uv run python main.py
  • Interactive docs at /docs
Data

In-Memory JSON

  • No database — flat JSON files in server/data/
  • Loaded once at process startup by mock_data.py
  • Held in module-level Python lists/dicts
  • Filtering happens in-process on every request
  • generate_data.py is an offline seed script

System Architecture

Three tiers, all running locally with no persistence layer. The frontend talks directly to the backend over HTTP — there is no proxy in front of the API, so CORS on the FastAPI side is what allows the cross-port browser requests.

Data Flow — Filter Selection Example

Filters are global and shared across views via a singleton composable, but each view is responsible for fetching its own data when a filter changes. Walking through selecting a warehouse on the Inventory page:

1

User interaction

User picks a warehouse in FilterBar.vue, bound via v-model="selectedLocation".

2

Shared composable state

selectedLocation is a module-level ref exported from useFilters.js — every component that calls useFilters() shares the same instance, so no props/events are needed to propagate the change.

3

Reactive trigger

Inventory.vue has a watch([selectedLocation, selectedCategory], loadInventory), so the ref mutation fires a reload.

4

Request builder

getCurrentFilters() reads the current ref values and returns { warehouse, category } (Inventory doesn't forward status/month — inventory has no time dimension).

5

API client

api.getInventory(filters) builds a URLSearchParams (skipping any value equal to 'all') and calls axios.get('http://localhost:8001/api/inventory?...').

6

FastAPI endpoint

GET /api/inventory receives warehouse/category as optional query params and calls apply_filters(inventory_items, warehouse, category).

7

In-memory filtering

apply_filters does an exact match on warehouse and case-insensitive match on category over the list mock_data.inventory_items (loaded at startup from inventory.json), returning a new filtered list.

8

Response

FastAPI validates and serializes the result against response_model=List[InventoryItem] and returns JSON.

9

Computed property

The response is assigned to a local items ref; a filteredItems computed property layers on client-side search text and low-stock-first sorting.

10

Render

<tr v-for="item in filteredItems" :key="item.sku"> re-renders the table with translated fields and stock-status badges.

Notes on Current State

Unimplemented endpoints referenced by the frontend

client/src/api.js calls /api/tasks (GET/POST/PATCH/DELETE) and /api/purchase-orders, but none of these routes exist in server/main.py. A CreatePurchaseOrderRequest model is defined but never wired to a route. The Tasks modal and "create purchase order" flow will 404 against the real backend today.

Orphaned view

views/Backlog.vue is a fully built backlog-management page that is not registered in main.js's router and has no nav link in App.vue. Backlog data is instead surfaced inline inside Dashboard.vue.

No persistence

All data lives in-memory for the lifetime of the backend process. Restarting main.py resets any state to whatever is in the server/data/*.json files — there is no database and no writes are persisted to disk.
